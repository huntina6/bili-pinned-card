## 用户需求
用户在 IDE 中准备实机运行 `node cli.js` 做交互向导测试时，被弹窗阻塞：

> 找不到 Node.js 二进制文件 "node"：路径不存在。请确保 Node.js 已安装且位于你的路径中，或者在 launch.json 中设置 "runtimeExecutable"（按钮：打开 launch.json / 取消）

需要解除该阻塞，让 IDE 与终端都能正确定位 Node 运行时，并说明交互向导的正确启动方式。

## 产品概述
本机不存在任何系统级 Node（无 `/usr/local/bin/node`、`/opt/homebrew/bin/node`、`/usr/bin/node`，也无 nvm/volta/fnm），唯一的 Node 是 IDE 托管运行时 `/Users/node/.workbuddy/binaries/node/versions/22.12.0/bin/node`（实测 v22.12.0）。IDE 的内置终端会把该运行时目录注入 PATH，因此在终端里 `node` 可用；而 IDE 进程自身（Dock/Finder 启动）不继承 shell PATH，所以「运行/调试」按钮找不到 `node` 并弹出该错误。

另有一个易被忽略的关键点：交互向导要求真实终端（stdin/stdout 均为 TTY）；用「运行/调试」按钮的默认控制台即使修好 Node 路径也不会进入向导，会直接提示跳过。

## 核心功能
1. **根因确认**：复核 Node 运行时的唯一位置与终端内可用性，形成可直接引用的绝对路径结论。
2. **终端启动方案（首选，零文件改动）**：给出在内置终端里启动向导的完整命令、TTY 与 CI 自检步骤、失败兜底命令。
3. **launch.json 配置方案（可选，需用户同意）**：提供两份运行配置（交互向导 / 非交互单次出图），明确必须使用集成终端作为控制台，并说明该文件位于未被忽略的目录、会产生 git 未跟踪文件及处理方式。
4. **实机验证清单**：验证终端能进入向导首屏、按键与返回上一步生效、Ctrl+C 退出码为 130；并记录「运行按钮」与「终端」两种方式的行为差异结论。



## 技术选型
- **运行时**：复用唯一可用的 IDE 托管 Node `v22.12.0`，绝对路径 `/Users/node/.workbuddy/binaries/node/versions/22.12.0/bin/node`；不新增任何依赖，不改动业务代码。
- **IDE 配置**：VS Code 系 `launch.json`（`version: 0.2.0`）标准 schema，`type: node` + `runtimeExecutable` + `console: integratedTerminal`。
- **验证手段**：`which -a node`、`node --version`、`node -e "console.log(process.stdin.isTTY, process.stdout.isTTY)"`、终端内实跑向导与退出码检查。

## 实施思路
分两层修复，遵循「最小改动优先」：

1. **首选零改动**：直接用内置终端运行。终端 PATH 已含托管运行时的 `bin` 目录，命令简化为 `cd 项目根 && node cli.js`；若遇 PATH 异常（例如通过任务运行器/非登录 shell 启动），用托管 Node 绝对路径兜底。启动前做 TTY 自检（须输出 `true true`）并确认 `CI` 未设置。
2. **可选治愈摩擦**：若坚持使用「运行/调试」按钮，则新建 `.vscode/launch.json`，用 `runtimeExecutable` 指向托管 Node，并把 `console` 设为 `integratedTerminal`——这是硬约束：默认的调试控制台没有 TTY，向导会被 `shouldInteract` 的 `stdin.isTTY && stdout.isTTY && !CI` 闸门直接跳过（仅打印一行跳过提示后转非交互运行）。此方案需用户显式同意，因为项目当前没有 `.vscode/` 目录且 `.gitignore` 未忽略它（现有忽略项仅 `node_modules/`、`output/`、`*.log`、`.DS_Store`、`.workbuddy/`）。

不采用需要 sudo 的系统级方案（如写入 `/usr/local/bin` 软链、`/etc/paths.d`），避免引入提权与全局副作用。

## 实施说明（执行要点）
- **绝对路径硬编码风险**：托管运行时路径含版本号（`versions/22.12.0/...`），IDE 升级 Node 后可能失效；在清单中注明失效表现与更换方式。
- **TTY 判定不可绕过**：任何「后台/管道/调试控制台」运行都不会进入向导，这是设计行为而非缺陷，需在清单中显式说明，避免误判为回归。
- **验证可观测性**：以「首个章节标题（登录状态）是否出现」「`node -e` 打印的 TTY 布尔值」「Ctrl+C 后 `echo $?` 是否为 130」作为判定点。
- **影响面控制**：仅新增一个 IDE 配置文件（可选）；不改 `cli.js`/`lib/*`，不触碰 `package.json`，不产生仓库业务改动；若新建 `launch.json` 建议同时说明「保留为本地未跟踪文件」或「追加 `.vscode/` 到 `.gitignore`」二选一，不擅自改动忽略规则。

## 架构设计
无架构变更。仅新增 IDE 侧启动描述文件，运行时仍由 `cli.js → lib/interactive.js（runInteractive → runWizard 步骤机）→ lib/watcher.js` 既有链路承担。

## 关键代码结构
`.vscode/launch.json`（核心字段，仅列结构与关键值）：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "交互向导（集成终端 TTY）",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/cli.js",
      "runtimeExecutable": "/Users/node/.workbuddy/binaries/node/versions/22.12.0/bin/node",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}",
      "skipFiles": ["<node_internals>/**"]
    },
    {
      "name": "非交互：单次出图",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/cli.js",
      "runtimeExecutable": "/Users/node/.workbuddy/binaries/node/versions/22.12.0/bin/node",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}",
      "args": ["--oid", "404135596", "--once", "--no-input"]
    }
  ]
}
```

终端启动（首选，零改动）：

```bash
cd /Users/node/bilicard/bili-pinned-card
echo "CI=[${CI:-未设置}]"        # 必须不是 true
node -e "console.log(process.stdin.isTTY, process.stdout.isTTY)"   # 期望 true true
node cli.js                       # 应出现「登录状态」章节
```
